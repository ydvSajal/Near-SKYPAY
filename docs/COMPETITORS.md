# Competitor evidence review

Research date: November 14, 2026 IST. This is our relevance assessment, not an organizer ranking. No competitor code was executed, dependencies installed, test badges independently reproduced, funds spent or live payment observed. Confidence refers to the described evidence, not overall security.

The current [project directory](https://nearhackathon.com/#projects) was opened. Its fetched representation exposed search/track controls but stayed at ?Loading the build log?; the browser host was unavailable. Therefore Real-World Money filter results and completeness of the watchlist could not be verified. Do not represent this as a complete directory census. Track relevance below comes from project descriptions/READMEs, not confirmed submission enrollment.

All fifteen watchlist repository identities were accessible through the GitHub connector. Several web-cache fetches failed initially; these are access-method failures, not missing repositories. `Mrsuxess/Steward` resolves to `Mrsuxess/STEWARD`. Clean Ledger is an adjacent security project, not business invoicing. None of the supplied links was proven unrelated to NEAR, but several are less relevant to SkyPay's workflow.

## Implementation evidence and implications

- [Cascade settler.ts](https://github.com/Timioni001/cascade/blob/main/services/settler/src/settler.ts): polling updates persistent records, checks isDepositRecorded before recording incoming success, and invokes receipt hooks. It records provider-reported SUCCESS; independent destination-receipt verification was not established by this file. SkyPay added startup read-only reconciliation and atomic financial/outbox writes, without treating provider progress as payment.
- [Remiglo poller.ts](https://github.com/lildosnear/Remiglo/blob/main/src/services/poller.ts): keeps quoted and observed output separate and handles each entity's errors. Its invoice expiry check runs before polling. This highlights the need for late-deposit/refund states rather than overwriting financial truth with a quote timer. SkyPay executable collection remains missing.
- [Bursar executor.ts](https://github.com/DCSteve96/Bursar/blob/main/app/src/executor.ts): quote signature check, payment-recipient binding, fee cap, separate settlement confirmation and owner-mediated failure recovery. The file's comment about confidentiality requirements is a competitor assertion, not adopted as official API guidance. SkyPay strengthened owner relay argument validation and retains unknown states instead of assuming failure.
- [STEWARD paymentExecutionService.ts](https://github.com/Mrsuxess/STEWARD/blob/main/src/pipeline/paymentExecutionService.ts): EXACT_OUTPUT generation and flags liveQuoteFetched/isSimulatedQuote. Offline catalog/price fallback is distinguishable from live output; inspected conversions include floating-point values. SkyPay preserves integer invoice amounts and fails closed on unavailable quotes.

Only selected implementation files in four repositories were inspected. This is a focused source review, not a repository security audit. No competitor code was copied. Gas sponsorship, vendor risk and cross-chain routing are already common claims; SkyPay's strongest prospective distinction is the demonstrable agent -> email invoice -> verified collection -> Notion/receipt/CSV -> constrained supplier journey. Today that journey is testnet-native and partially verified, with cross-chain execution missing.
